## 1. 真实 UTF-8 Markdown 文件，暖缓存

scripts/make-fixtures.ps1 写入重复标题、段落、中文、粗体和列表，实际写盘，不是稀疏文件。examples/bench.rs 每项 30 次，数字为毫秒。首分页限制为 128 KiB 读取、最多 2048 行；这些数字**不包含 GDI 排版和绘制**。

| 文件 | 打开 p50 | 首分页读取+解析 p50 | 首分页 p95 | 中部 p50 | 尾部 p50 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 1 MiB | 0.013 | 1.119 | 1.259 | 1.163 | 0.210 |
| 64 MiB | 0.013 | 1.122 | 1.259 | 1.203 | 0.192 |
| 1 GiB | 0.012 | 1.051 | 1.192 | 1.066 | 0.184 |

尾部分页内容更少，不能与首分页当作同等工作量比较。设备缓存与重复内容使结果偏向理想情况；未进行断电冷缓存、远程盘或低端设备测试。

## 2. 真实原生窗口交互

scripts/ui-smoke.ps1 使用隐藏 Windows 原生窗口、隔离的临时便携配置和进程内 GDI 截图。测试真实搜索框输入、Enter 对应后台通路、主题切换、百分比跳转、50 次源码/预览和主题切换、GDI 句柄稳定性与正常退出。下面是两次**单次运行**，不是统计分位数：

| 输入 | 创建窗口 | 首分页排版完成 | 首次测试抓图完成 | 进程私有内存 | 工作集 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 807 B 演示文档 | 72.62 ms | 79.92 ms | 108.37 ms | 4.59 MiB | 24.38 MiB |
| 1 GiB 实体 Markdown | 42.80 ms | 74.86 ms | 87.16 ms | 7.06 MiB | 26.39 MiB |

时间包含启动测试进程和 10/30 ms 轮询粒度；“首次测试抓图”不是显示器上用户可见像素的严格测量。内存是在搜索、跳转和切换后的采样，包含系统 GUI 组件。GDI 句柄从 26 增长至 27 后稳定（字体缓存），小文件 27 → 27。

发布前使用最终 **640 KiB** 二进制再次复测：807 B 文档首分页排版 85.66 ms、私有内存 4.72 MiB；1 GiB 文档首分页排版 78.80 ms、私有内存 6.69 MiB、工作集 26.04 MiB。两次原生交互测试均通过，仍为暖缓存下单次结果。

## 3. 极端输入回归

17 个核心测试覆盖：

- 空文件、UTF-8 BOM、CRLF、中文和 emoji 字节边界。
- 4 MiB 无换行长行，1,000,000 个密集换行。
- 随机二进制输入、不合法 UTF-8、UTF-16 BOM 明确拒绝。
- 文件打开期间外部截断。
- 搜索跨 256 KiB I/O 边界、重叠匹配、回绕、取消、空查询和最大查询长度。
- 不同 Markdown 围栏类型/长度、列表和样式、危险链接拒绝。
- 设置校验、持久化和原子替换。
- **100 GiB 稀疏文件**的尾部读取及 64-bit 偏移。此测试验证偏移/内存边界，不代表读取了 100 GiB 实际内容，更不是 100 GiB 全文搜索测速。

## 9. v0.1.13 纯文本、日志与旧编码

本机 Windows 11 x64，Rust 1.99 MSVC Release，暖缓存，2026-10-24。合成文件由被忽略的 `target/tmp/perf/make-plain-fixtures.py` 生成并写盘（不是稀疏文件）；`examples/bench.rs` 现按文件自己的格式解析分页，并在最后做一次完整目录扫描。分页数字为 5 次中位数（毫秒），目录为单次。

| 文件 | 识别 | 打开 | 首分页 | 中部 | 尾部 | 目录 |
| --- | --- | ---: | ---: | ---: | ---: | --- |
| big.log，1 GiB，约 1070 万行（7 天 log4j 风格，约千分之一 ERROR 带堆栈） | 日志 / UTF-8 | 0.24 | 0.66 | 0.66 | 0.12 | 时间索引扫描全部 1,073,741,912 字节 **1851 ms**（约 550 MiB/s），175 项，10,387 个错误、49,031 个警告 |
| novel.txt，25 MB UTF-8，30 卷 3000 章 | 纯文本 | 0.22 | 0.32 | 0.28 | 0.07 | 章节 **21.6 ms**，3030 项 |
| novel-gbk.txt，8 MB GBK | 纯文本 / GB18030 | 2.02 | 1.25 | 1.22 | 0.31 | 章节 **74.0 ms**，1500 项 |

- 日志目录不再限于前 16 MiB，而是以同样可取消的 256 KiB 分块读完整个文件；内存不随文件增大：每行只保留 4096 字节前缀，时间段最多 240 个（超过即合并为更粗的时间段），无时间戳日志最多列 1000 个错误行。大于 32 MiB 的日志在目录区显示扫描百分比。Markdown 仍为 16 MiB、纯文本章节为 256 MiB。
- 旧编码只在文件开头 64 KiB 明显不是 UTF-8 时启用；UTF-8 文件的读取路径没有改变。GB18030 由 Windows `MultiByteToWideChar` 解码，打开时多读的 64 KiB 样本使打开时间约 2 ms；分页按字符从行首走到边界，不会切开汉字。
- 以上为单机暖缓存样本，不是冷启动、机械硬盘或网络盘的保证。

## 10. v0.1.14 目录树、筛选、文档内链接与查找结果

本机 Windows 11 x64，Rust 1.99 MSVC Release，暖缓存，2026-10-31。合成文件由被忽略的 `target/tmp/perf/make-spec-fixture.py` 生成并写盘：仿 Word 转换的数据模型说明书，`## 目 录` 下 471 个普通列表项，正文 8680 个标题全为 `####` / `#####`、层级只在编号里，每张表 11 列，共 4,013,545 字节。`examples/bench.rs` 新增目录树、目录链接与（给出查询词时）查找全部匹配的计时；分页为 5 次中位数，其余为单次（查找为 5 次中位数）。两轮结果一致。

| 项目 | 结果 |
| --- | --- |
| 完整目录扫描（含层级与锚点） | **10.6 / 10.7 ms**，8680 项 |
| 其中层级与锚点（`assign_depths` + `Contents::new`） | **3.8–4.0 ms** |
| 打开时列出的行（超过 500 项时较深层级折叠） | 472 行 |
| 首分页目录列表链接（`toc::link`） | 471 项，**0.13–0.25 ms** |
| 查找全部匹配：20 处 / 无匹配 / 达到 1000 处上限 | **0.48 / 0.47 / 1.68 ms** |
| 查找带下划线的名称（同时找 `\_` 转义写法，3 个搜索串） | 1 处，**0.56 ms** |

- 目录上限由 4096 项提高到 16384 项（每项仍最多 160 字符、Markdown 仍只扫描前 16 MiB），常见的上万标题转换文档可以完整列出；内存仍由上限决定，不随文件增大。筛选每次输入在 UI 线程上对已小写的标签做子串比较，16384 项以内为微秒到毫秒级；行绘制只画可见行。
- 查找全部匹配与单次查找相同，以 256 KiB 分块读取、可取消，最多列出 1000 处并停止；每处只额外读取所在行前后各 240 字节。Markdown 中含标点的查询词同时查找转换工具写出的反斜杠转义形式（最多 3 个搜索串，同一次读取中合并），对耗时没有可测出的影响。文件在 4 MiB 以上时结果区显示读取百分比。
- 在一份真实的转换文档上（不在仓库中）：4.9 MiB、9204 个标题的目录扫描约 14 ms，打开时 452 行，451 个目录列表项全部链接，查找一个常见字段名 501 处约 1.7 ms。
- 查找默认不区分英文字母大小写：每个 256 KiB 分块先复制一份转成小写再查找。同一合成文档上，含字母的查询（`fmaterialid`，1000 处上限）约 3.8 ms，区分大小写时约 0.7 ms；不含 ASCII 字母的查询（如 `表单2307`）不需要转换，两种方式耗时相同（0.5–0.7 ms）。1 GiB 日志上找不到的查询：含字母约 **726 ms**、区分大小写约 221 ms，中文查询两种方式约 210–215 ms（单次，`examples/bench.rs` 的 `find_any_case_p50_ms`）。都在后台进行、可取消，显示读取百分比。

### 拖动滚动条

被忽略的 `target/tmp/drag-probe.ps1` 在副屏（120 DPI，默认窗口）向隐藏的阅读器发送窗口消息：按下滑块，80 步从顶拖到底，每步间隔 8 ms，松开；记录每步消息处理的阻塞时间、排版次数与耗时，每步之后再计一次内存位图绘制（拖动时每次移动都要画）。不注入全局鼠标输入。

| 文件 | 改前：80 步中排版 / 最长排版 / 每步 p90 / 最长 | 改后：排版 / 最长排版 / 每步 p50 / p90 / 最长 |
| --- | --- | --- |
| 真实转换文档（不在仓库中，4.9 MiB，表格为主） | 36 次 / 47.6 ms / 30.7 ms / 47.8 ms | 80 次 / 8.9 ms / 6.8 / 13.9 / 19.6 ms |
| 合成转换文档（同上，4.0 MB） | 36 次 / 49.5 ms / 32.7 ms / 43.6 ms | 80 次 / 12.5 ms / 6.7 / 14.6 / 29.8 ms |
| 25 MB 小说 | 61 次 / 7.5 ms / 5.8 ms / 7.7 ms | 81 次 / 2.0 ms / 4.3 / 5.4 / 6.0 ms |
| 1 GiB 日志 | 51 次 / 12.9 ms / 4.4 ms / 6.8 ms | 80 次 / 2.0 ms / 3.6 / 4.8 / 5.8 ms |

- 改前：每次移动都把整页（最多 2048 行，表格行很多）重新排版，表格为主的一页要 20–50 ms；Windows 让鼠标消息优先于 WM_PAINT 和计时器，拖得快时一半的移动没有排版也没有重绘，画面停住再跳。改后：拖动时只排版滑块附近的块（前 24 块、后 64–176 块，按窗口高度），同时只读一页、读完跟随最新位置，每次移动后至多每 8 ms 直接重绘一次；松开后排完整一页。所有文件都停在文件末尾。
- 最终构建在同一会话后段复测时，本机后台有约 44% 的 CPU 负载（其他程序）：真实文档每步 p90 16.5–21.8 ms、合成文档 19.9–23.8 ms，最长排版 11.8–14.9 ms，仍是每步都排版并重绘；同时 1 GiB 日志 p90 5.9 ms。表格为主的页面上，p90 仍接近 60 Hz 的一帧（16.7 ms）。
- 以上为单机暖缓存样本，不是冷启动、机械硬盘或网络盘的保证。
