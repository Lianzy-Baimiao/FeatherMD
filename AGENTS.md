# FeatherMD contributor instructions

- Keep the Windows GUI native and dependency-light. No browser engine or full-document allocation. Network access has only two exceptions: the opt-in update check (src/updater.rs), and individually confirmed HTTP(S) image loads (src/ui/pictures/web.rs). Update checks make one HTTPS GET of the public GitHub "latest release" record via system WinHTTP, off by default, at most daily when enabled, manual otherwise. Updates must never download, install or upload anything; keep any test URL override loopback-only.
- File reading and searching must remain off the UI thread. Preserve the 128 KiB read window, 4096-byte long-line segments, 2048-line layout limit, and cancellable 256 KiB search chunks. Outlines follow the format (src/plain.rs, src/outline.rs): Markdown headings within 16 MiB, plain-text chapters within 256 MiB, and a log's time index over the whole file, read in the same cancellable 256 KiB chunks with bounded output (at most 240 time ranges or 1000 error lines). The outline lists at most 16384 entries; Find's list of matches reads the file in the same cancellable chunks and stops at 1000 matches. A file that is clearly not UTF-8 is decoded with the system's legacy code page (src/encoding.rs: GB18030 for GBK, Big5, Shift-JIS…); the UTF-8 path must stay unchanged.
- Do not use mmap: externally edited/truncated files must stay safe.
- Never silently take default associations or write UserChoice. Registration is opt-in, per-user, and must preserve other applications.
- Do not execute Markdown HTML, scripts or local links. HTML tags only shape text (src/html.rs); script/style/embedded content stays hidden. External HTTP(S) links need a user confirmation. Remote images must never load automatically.
- Automatic local images are off by default (Settings → Reading → Show images). When on, only local raster files are read (src/image.rs rules, src/ui/pictures.rs loader): drive-letter paths on fixed/removable drives, no links, junctions, network drives, shares, devices or online-only cloud files; bounded size, pixels and cache; decoded off the UI thread, content-sniffed before any decoder sees it. A user may click an HTTP(S) image placeholder and confirm its exact URL to load that image only, even with local images off. Use anonymous WinHTTP GETs, no cookies/authentication/referer/redirects, default certificate validation, bounded time/queue/bytes/pixels/cache, no disk writes or persisted permissions. Reopening/F5 must clear remote pixels and cancel stale requests; tests use loopback only.
- Tests before release: cargo fmt --check; cargo clippy --all-targets -- -D warnings; cargo test; cargo build --release; scripts/ui-smoke.ps1; scripts/navigation-smoke.ps1 (headings and wrapped shapes); scripts/about-smoke.ps1, scripts/typography-smoke.ps1, scripts/settings-smoke.ps1, scripts/update-smoke.ps1, scripts/table-smoke.ps1, scripts/image-smoke.ps1, scripts/formats-smoke.ps1 and scripts/outline-smoke.ps1 (light and dark); scripts/editor-smoke.ps1; scripts/i18n-smoke.ps1 (all interface languages, no clipped text). Build the stand-ins first: cargo build --release --example editor_probe --example update_server.
- "Edit" only hands the document path to the user's chosen editor as one quoted argument. Never write documents, file associations or default apps from it.
- Read docs/PROGRESS.md before continuing. Record precise evidence and limitations; distinguish warm-cache parsing, GUI first layout, real files, and sparse files.
- Do not publish ignored fixtures, local settings, local build environment scripts, or other workspace data. Never force-push.
- Use MSVC for distributable Windows binaries with static CRT. The local host has a GNU default toolchain; use cargo +stable-x86_64-pc-windows-msvc. If needed, source ignored target/dev-env.ps1 on this development machine. Do not commit machine-specific paths.
- Do not run native GUI/dialog smoke tests on the user's desktop without fresh explicit permission. Hidden launch flags do not stop native modal dialogs flashing or stealing focus. Run local fmt, Clippy, unit tests and package validation silently; run GUI, activation and lifecycle tests on a disposable Windows runner. Never pass `-AllowDesktopUi` automatically. An interrupted GUI suite is not a pass.
- With explicit secondary-monitor permission, use `-SecondaryMonitor`, never the primary-desktop override. It requires the rebuilt containment marker, confines the reader and its modal windows before display, vetoes activation on the UI thread, and records boundary/foreground checks. Do not inject global mouse/keyboard input or launch external browsers, editors or system settings during those tests. Installation/trust/default-association tests still belong on a disposable runner.
