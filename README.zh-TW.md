**輕一點，讀更多。** 一個用 Rust 編寫的 Windows 原生 Markdown 檢視器，也能讀純文字與大型日誌。介面支援简体中文、繁體中文、English 和日本語。

[下載單一檔案 EXE](https://github.com/Lianzy-Baimiao/FeatherMD/releases/latest) · [效能與驗證](docs/PERFORMANCE.md)（簡體中文） · [實作說明](docs/ARCHITECTURE.md)（英文）

![FeatherMD 繁體中文閱讀介面](docs/reading-light.zh-TW.png)

頂部是 34 px 高的安靜標題列：左邊只有羽毛標誌和文件名稱；右邊**開啟 / 尋找 / 外觀 / 更多**四個圖示同一尺寸、同一線寬，滑鼠停留時出現淺色圓角底並顯示名稱和快速鍵。視窗按鈕整欄反白，關閉按鈕停留時為紅色。預覽與原始碼的**眼睛 / 程式碼**開關在底部狀態列左側。圖示為 GDI+ 反鋸齒向量，直線對齊像素格線、曲線圓潤平滑。

**外觀只佔一個按鈕**（半黑半白的圓）：按一下展開淺色 / 深色 / 跟隨系統，第四列「更多主題…」進入設定裡的 20 款主題。也可以按 **Ctrl+T**，用方向鍵或 Tab 選擇、Enter 確認、Esc 取消。

**內文按右鍵 → 編輯**（Ctrl+E）：用你選擇的編輯應用程式開啟目前文件；FeatherMD 本身維持唯讀，儲存後按 F5 重新載入並停在原位置。

**一鍵複製**：滑鼠移到程式碼區塊、引文或表格上，右上角會出現「複製」按鈕；程式碼複製原文（不含圍欄），表格複製為以定位字元分隔的儲存格。

目錄開關仍位於目錄區域：展開時在「目錄」標題右側，隱藏後在內容區左邊緣。尚未開啟文件時不顯示空的目錄欄。

新設定預設跟隨系統；系統應用程式色彩改變時會重新整理，手動選擇的淺色或深色不會被覆蓋。切換主題會保留閱讀位置，閱讀模式與主題偏好在重新啟動後保留。

本文後面的截圖以简体中文介面為主；所有畫面都能以繁體中文顯示（見[介面語言](#介面語言)）。

## 為什麼做這個

開啟一份 Markdown，不應該先啟動一個瀏覽器。

FeatherMD 使用 Win32 + GDI/GDI+，沒有 Electron、WebView、JavaScript 或遙測，預設不連網；更新檢查只在主動開啟或手動檢查時存取 GitHub Releases；網路圖片只有逐張點選並確認後才下載。v0.1.14 的 Windows x64 EXE 約 **1.20 MiB**（含四種介面語言、程式碼醒目提示與本機圖片解碼），無須安裝 .NET、VC++ 執行階段或其他第三方執行環境。

**大檔案不是先全部載入再顯示：** 每次只讀取附近 128 KiB，在背景讀取與搜尋，前景只繪製可見的行。檔案總長度不決定第一頁需要配置的記憶體。

## 使用

1. 從 Releases 下載 **FeatherMD.exe**，放到喜歡的資料夾，按兩下執行。
2. 拖入 Markdown、文字或日誌檔案，或按 **Ctrl+O**。
3. 在左側目錄按一下標題即可跳轉；按「目錄」標題右側的按鈕收起，按內容區左邊緣的按鈕展開，也可以按 **Ctrl+B** 切換，狀態會保存。
4. 底部狀態列左側的眼睛 / 程式碼開關切換預覽 / 原始碼（Ctrl+R），頂部外觀按鈕選擇主題；省略號「更多 → 設定…」（Ctrl+,）調整主題、透明度、字型字級、是否顯示圖片、預設編輯應用程式與介面語言，自動換行與閱讀寬度也在「更多」中。
5. **更多 → 關於 FeatherMD**（F1）查看版本、快速鍵和閱讀說明，或前往 GitHub 專案首頁、愛發電支持作者。外部連結會先確認，再交給預設瀏覽器開啟。
6. **更多 → 檢查更新…** 手動檢查新版本；也可以在設定的「更新」頁開啟啟動時自動檢查（預設關閉）。
7. **更多 → 介面語言 / Language…** 切換介面語言，儲存後立即生效。

支援 Windows 10（1607+）/ Windows 11 **x64**。目前實測環境為 Windows 11 x64；其他版本尚未逐一實機驗證。沒有安裝程式，不需要系統管理員權限。尚未購買程式碼簽章憑證，Windows SmartScreen 可能提醒未知的發行者；請核對來源和 SHA-256，不要關閉系統防護。

### 目錄與搜尋

**目錄篩選：** 目錄上方的篩選框輸入即篩，以空格分隔的多個詞都要出現（不區分大小寫），符合項目連同它的上層一起列出，上層以淺色顯示；按 Enter 跳到第一項，按 Esc 清除。

**階層目錄：** 縮排跟隨標題層級。從 Word 等轉換來的文件常把所有標題寫成同一級（例如全是 `####`），階層只在編號裡（`1`、`1.1`、`1.1.1`），這時依編號巢狀排列，沒有編號的標題歸到它前面的編號標題下。條目很多時，較深的層級先摺疊起來，開啟時最多列出約 500 項；按左側三角形展開或摺疊。目錄列更緊湊，同一畫面能看到更多條目。依編號巢狀排列的文件，內文標題的字級也跟隨階層（`1` 最大，`1.1.1` 依序變小），不再全部一樣大。

**Ctrl+F 搜尋結果：** 輸入文字後，右側面板列出全文所有符合項目：行號、前後文，符合的文字加底色；內文裡的符合處也會標出，目前這一處顏色更深，表格較寬時會自動橫向捲到符合項目所在的欄。按 Enter / F3 跳到下一處，Shift+Enter / Shift+F3 上一處，按一下結果直接跳轉，狀態列顯示「第 3 / 57 處 · 第 905 行」。最多列出前 1000 處，之後繼續按 Enter 仍能逐一尋找。視窗太窄時面板自動隱藏，尋找照常。預設不區分英文字母大小寫（搜尋 `readme` 也能找到 `README`），按搜尋框右側的 **Aa** 或 **Alt+C** 切換為區分大小寫；搜尋在背景以 256 KiB 分塊進行，可取消。Markdown 裡轉換工具常把底線寫成 `\_`（如 `T\_BD\_CONTACT`），直接搜尋 `T_BD_CONTACT` 也能找到，結果中顯示為不帶反斜線的文字。

**文件內連結：** `[文字](#標題)` 這樣的頁內連結會跳到對應標題（依 GitHub 的錨點規則，也認得標題原文）。轉換來的文件裡「目錄」下方的一般清單項目，如果正好是標題的文字（至少 3 項、大多數能對上），會自動變成連結並依層級縮排。作者自己寫的連結保持不變；指向其他檔案的連結仍不會開啟。

### 純文字與日誌

除了 Markdown，也可以直接閱讀 **.txt 純文字**和 **.log 等日誌**，目錄依格式區分：

| 格式 | 如何辨識 | 內文 | 目錄 |
| --- | --- | --- | --- |
| Markdown | .md / .markdown / .mdown / .mkd | 排版預覽 | `#` 標題 |
| 純文字 | .txt 及其他文字檔 | 每行照原樣顯示，保留行首縮排與空行，自動換行 | 章節：`第三卷`、`第十二章`、`第3回`、`第2節`、`序章` / `番外`、`Chapter 12` / `Part One`，以及底線（`===` / `---`）標題；沒有章節的公文依 `一、`、`（一）` 編號 |
| 日誌 | .log、輪替的 `app.log.1`、.out；行首多為時間戳記的 .txt 也當日誌讀 | 等寬字型，時間戳記淡顯，`ERROR` / `FATAL` 紅色、`WARN` 琥珀色，不顯示 ANSI 色碼 | **時間索引**：依日期 → 時段分組，每段標出錯誤與警告數，含錯誤的時段為紅色，按一下跳到該段第一行；沒有時間戳記的日誌（如編譯輸出）列出錯誤行 |

時段長度依日誌跨度自動選擇（1 分鐘到 1 週），目錄最多 240 段。可辨識 ISO 8601、log4j / Spark、syslog、Android logcat、glog、Nginx / Apache 存取日誌，以及 logfmt / JSON 裡的時間與 `level=error` 等常見寫法。日誌目錄在背景以 256 KiB 分塊掃描**整個檔案**，大檔案顯示進度，開啟其他檔案或隱藏目錄即取消；內文仍只讀取附近 128 KiB。實測 1 GiB、約 1070 萬行的日誌約 1.9 秒建好時間索引，25 MB、3000 章的小說約 22 ms 辨識完章節（暖快取，見 [PERFORMANCE.md](docs/PERFORMANCE.md)）。

**不是 UTF-8 的檔案**（例如較早的 GBK 或 Big5 小說）依 Windows 的系統舊編碼讀取：繁體中文系統為 Big5，簡體中文為 GB18030（相容 GBK），日文為 Shift-JIS。狀態列顯示實際使用的編碼，搜尋也依該編碼進行；UTF-8 檔案不受影響。原始碼模式（Ctrl+R）顯示原文，複製保留定位字元。

### 閱讀排版、程式碼醒目提示與 HTML 標籤

預設字級 16 px，內文行高約 1.6 倍；空行是比一行略短的段落間距，標題上方留白多於下方，一、二級標題下有細線（換行的標題只在最後一行畫線）。清單換行後與項目文字對齊，工作清單顯示為核取方塊；引文是灰色直線與次要色文字；表格隔列淺色斑馬紋。

程式碼區塊是帶圓角底板的等寬文字，字級略小於內文，左上角標出語言。**程式碼醒目提示**支援 Rust、C/C++、C#、Java/Kotlin/Scala、Swift、Go、JavaScript/TypeScript、Python、Ruby、PHP、Lua、SQL、Shell、PowerShell、批次檔、JSON、YAML、TOML/INI、Dockerfile、CSS、HTML/XML 與 diff：關鍵字、型別、函式名稱、字串、數字、註解等顏色隨主題調和，跨行的區塊註解和多行字串保持著色。行內程式碼和 `<kbd>` 按鍵是圓角小底板。

常見 **HTML 標籤**按排版顯示：`<p>`、`<h1>`–`<h6>`、`<br>`、`<hr>`、`<b>`/`<strong>`、`<i>`/`<em>`、`<u>`、`<s>`/`<del>`、`<code>`、`<kbd>`、`<mark>`、`<sub>`/`<sup>`、`<a>`、`<img>`、`<blockquote>`、`<ul>`/`<ol>`/`<li>`、`<pre>`、`<div>`/`<span>`/`<center>`、`<details>`/`<summary>`（一律展開），以及 `align` 屬性與 `text-align` 樣式的置中 / 靠右、常用字元實體。許多 README 開頭的 `<h1 align="center">` 也會進入目錄。`<script>`、`<style>`、`<iframe>` 等內容既不顯示也不執行；標籤只改變排版，從不執行任何東西。

### 主題與透明度

**更多 → 設定… → 外觀**：20 款主題，淺色在前、深色在後——跟隨系統、淺色、**素白**（純白紙面）、霧灰、天青、護眼、**書本**（暖白紙頁放在亞麻底色上）、**古籍**（米黃宣紙、墨色內文、朱砂強調與雙線欄框）、**報紙**（暖灰新聞紙與深藍連結）、豆沙綠、櫻粉、**丁香**；深色、**暮色**（比深色更柔和的夜讀灰）、**極夜**（冷調石板藍）、夜藍、**深海**（深青底色）、**紫夜**、**咖啡**（暖棕與琥珀色）和純黑（OLED）。點選即在閱讀視窗即時預覽，方向鍵可在卡片間移動；「取消」或 Esc 還原，儲存後重新啟動仍保留。程式碼醒目提示的顏色隨每款主題調和。

**視窗不透明度** 30%–100%，每檔 5%，拖曳或用方向鍵調整；只作用於閱讀視窗，設定視窗維持不透明。100% 時不啟用分層視窗。所有主題的內文與背景對比度不低於 9.8:1，次要文字不低於 4.3:1，連結不低於 4.5:1（有單元測試）。

### 右鍵編輯與預設編輯應用程式

FeatherMD 唯讀。需要修改時，在內文**按右鍵 → 編輯**，或按 **Ctrl+E**，目前文件會以單一加引號的參數交給編輯應用程式；儲存後回到閱讀器按 **F5**，重新載入並保持閱讀位置。右鍵選單還包含複製、全選目前分頁、尋找與重新載入，**Shift+F10** / 選單鍵同樣可用。

**更多 → 設定… → 編輯** 選擇預設編輯應用程式：

- **系統預設**：使用 Windows 為該檔案類型登錄的「編輯」方式；沒有登錄時改用系統記事本。
- **記事本**，以及自動偵測到的 VS Code、VSCodium、Cursor、Typora、MarkText、Notepad++、Sublime Text、Zed、EmEditor（只檢查固定安裝位置與 App Paths 登錄，不掃描磁碟）。
- **瀏覽…** 選擇本機磁碟上任意 .exe。只接受以磁碟機代號開頭的絕對路徑，不能選 FeatherMD 本身。

找不到編輯應用程式時會提示，並可直接重新選擇。這個設定不會修改 Windows 的預設開啟方式或檔案關聯。

### 一鍵複製程式碼區塊、引文與表格

在預覽中把滑鼠移到程式碼區塊、引文或表格上，右上角會出現**複製**按鈕，按一下即可複製整個區塊：

- **程式碼區塊**：複製檔案裡的原文，不含 ```` ``` ```` 圍欄行；縮排程式碼去掉一層縮排；定位字元保留，行與行之間為 CRLF。
- **引文**：複製畫面上顯示的文字，同一行自動換行的部分不會多出換行。
- **表格**：每列複製為以定位字元分隔的儲存格，可直接貼到試算表軟體。

很長的程式碼區塊向下捲動時，按鈕停在可見部分的頂端，不必捲回開頭。表格比內文窄時，按鈕放在表格右側，不遮住表頭。複製後按鈕顯示約 1.5 秒的勾號，狀態列說明複製了什麼；區塊超出目前快取分頁（約 128 KiB）時只複製已載入的部分，狀態列同樣會說明。原始碼模式沒有複製按鈕，請按字元選取後複製。

### 顯示圖片

**更多 → 設定… → 閱讀 → 顯示圖片**，**預設不勾選**。不勾選時，本機圖片顯示為「[圖片: 替代文字]」，不會自動讀取圖片。

勾選後自動顯示**本機上的圖片**：相對路徑從文件所在資料夾開始（`/assets/a.png` 也一樣），以磁碟機代號開頭的絕對路徑與 `file:///C:/…` 也可以。格式按檔案內容辨識（PNG、JPEG、GIF、BMP、TIFF、ICO），不看副檔名；JPEG 依 EXIF 方向轉正，透明部分透出主題底色，GIF 顯示第一格。圖片按 CSS 像素隨 DPI 縮放，`<img width="…" height="…">` 可指定大小，太寬時縮到內文寬度、太高時不超過閱讀區；只有圖片的行（Logo、截圖、徽章）和段落裡的小圖示都會顯示，帶連結的圖片可以點按。

**手動載入網路圖片（v0.1.10）：** 在預覽中點選 HTTP(S) 圖片的「點選載入網路圖片」，核對位址並確認後，只載入該位址的圖片；不必開啟「顯示圖片」。失敗可重試，相同位址共用記憶體快取。不自動下載其他圖片，不傳送 Cookie、登入憑證或來源頁，也不儲存檔案；F5、重新開啟文件或重啟後須再次確認。圖片網站會收到你的 IP 位址。僅支援直接回傳點陣圖片的 HTTP(S) 位址，不跟隨轉址；SVG/WebP 和表格儲存格圖片尚不支援。

### 表格

GitHub 風格的管線表格（表頭列 + `| --- | :-: | --: |` 分隔列）顯示為帶表頭底色和框線的表格，儲存格內支援粗體、行內程式碼和連結，分隔列裡的冒號決定靠左、置中或靠右對齊。

欄寬隨視窗自動調整：放得下時每欄保持內容寬度；放不下時先收窄最寬的欄，短欄維持原樣，儲存格內按詞或中文字元換行，逗號、句號等標點不會出現在行首。視窗變窄、隱藏目錄或縮放字級時立即重新排版。

欄太多、連最窄的可讀欄寬（約 6 個字）都放不下時，只有這張表格水平捲動（底部捲軸、Shift+滾輪或左右方向鍵），內文和放得下的表格維持不動。關閉自動換行時，表格保持內容寬度，與內文一起水平捲動。

轉換工具常在真正的表頭上方寫一列空表頭（`|  |  |`）。表頭儲存格全部為空時，這一列只留一道窄縫，下面的第一列顯示為表頭。

### 按字元選取

預覽和原始碼（Ctrl+R）都可以用滑鼠按字元拖曳選取：按兩下選取一個詞，Shift+按一下延伸選取範圍，拖到內文上下邊緣外會自動捲動並繼續選取。Ctrl+A 選取目前分頁，Esc 取消選取，Ctrl+C 或右鍵「複製選取的文字」複製；沒有選取時複製目前可見的內容。

- **預覽**複製畫面上的文字：同一段落自動換行的幾行連成一行（換行處去掉的空格會補回），段落之間為 CRLF；表格儲存格裡的文字同樣按字元選取（按兩下選取儲存格裡的一個詞），跨儲存格時以定位字元分隔、跨列時以 CRLF 分隔，選取整列則複製為以定位字元分隔的儲存格；圖片複製它的替代文字。縮放字級、改變視窗大小或圖片載入後，選取範圍仍是原來那些字。
- **原始碼**複製檔案裡的**原文**：定位字元維持為定位字元，中文與 emoji 不會被截斷，行與行之間為 CRLF，超長單行拆開顯示的片段之間不會多出換行。

選取範圍超出目前快取分頁（約 128 KiB）時只複製已載入的部分，狀態列會說明。複製單一程式碼區塊、引文或表格時，用它右上角的複製按鈕更方便。

### 檢查更新

更新來源是本專案的 [GitHub Releases](https://github.com/Lianzy-Baimiao/FeatherMD/releases)。

- **手動檢查**：更多 → 檢查更新…，開啟設定的「更新」頁並立即檢查。結果顯示「已是最新版本」、「發現新版本」（含版本名稱與發布日期）或失敗原因（網路、Proxy、GitHub 存取頻率限制等）。
- **啟動時自動檢查**：在「更新」頁勾選並儲存，**預設關閉**。開啟後在啟動約 3 秒後於背景檢查，每 24 小時最多一次；失敗時不打擾，下次啟動再試。
- **發現新版本**時，頂部「更多」按鈕出現一個小圓點，選單項目顯示「發現新版本 vX.Y.Z…」，升級後自動消失。「前往下載頁面…」會先確認，再用預設瀏覽器開啟對應的 Release 頁面。

檢查只透過 Windows 內建的 WinHTTP 以 HTTPS 要求 `api.github.com` 上公開的版本資訊，沿用系統 Proxy 設定和憑證驗證；不上傳文件、設定或其他資料，也**不會自動下載或安裝**任何檔案。關閉自動檢查且不按「立即檢查」時，FeatherMD 不會存取 GitHub；網路圖片與檢查更新分開控制，始終需要逐張確認。「更新」頁的「隱私說明…」離線顯示完整的隱私說明（隨套件附帶 docs/PRIVACY.md）。

### 右鍵開啟方式與預設應用程式

![檔案關聯設定](docs/file-associations-menu.png)

- 先將 EXE 放在**固定位置**。
- 按 **更多 → 檔案關聯 → 加入右鍵開啟方式（Markdown / 純文字 / 日誌）**，即可登錄到目前使用者的開啟方式清單，不彈出確認方塊或系統設定。
- 需要按兩下 .md 時預設用 FeatherMD 開啟，請按 **更多 → 檔案關聯 → 設為 .md 預設應用程式（系統確認）…**。會自動完成登錄並開啟 Windows 預設應用程式設定；選擇 **.md → FeatherMD**。較舊的 Windows 可能顯示預設應用程式首頁，需要搜尋 .md。
- 如果清單找不到 FeatherMD：確認正在執行的是**固定位置裡的新版 EXE**，再次執行上述登錄或設為預設的操作，關閉再開啟 Windows 預設應用程式頁面。在應用程式清單搜尋 FeatherMD，或在檔案類型搜尋 `.md`；仍不顯示時，可在「選擇其他應用程式」中瀏覽到該 EXE。登錄到清單不等於已成為預設應用程式。
- 也可以在 .md 檔案按右鍵 → 開啟檔案 → 選擇其他應用程式 → FeatherMD → 一律使用。
- 支援登錄 .md / .markdown / .mdown / .mkd / .txt / .text / .log。
- 「移除開啟方式登錄…」只移除 FeatherMD 自己的登錄項目。

Windows 10/11 要求使用者在系統介面確認預設應用程式，一般桌面程式沒有受支援的靜默設定方式。因此「加入開啟方式」可以靜默完成，「設為預設」仍需系統確認。移動 EXE 後需要重新登錄；移除登錄不會自動選擇另一個預設檢視器。

具體相容範圍及微軟文件見[檔案關聯說明](docs/FILE_ASSOCIATIONS.md)（簡體中文）。

### 目錄與導覽

- 自繪標題列、邊框和視窗按鈕，沒有獨立工具列，讓內文有更多空間。
- 可隱藏的分級標題目錄可獨立以滾輪捲動，按一下標題即可定位；目錄在背景擷取，不延遲第一頁。
- 自繪垂直 / 水平捲軸支援拖曳和在軌道上翻頁；快速拖離快取再返回時，過期的分頁結果不會把閱讀位置拉走。短檔案隱藏用不到的捲軸。
- 大檔案快速拖曳捲軸時，只排版滑塊附近的內容，每次移動都立即重繪；放開後再排完整一頁。表格很多的文件拖曳也不再卡頓。
- End 會顯示完整的最後一屏，最後一段很長且自動換行時也能到達真正的結尾。PageUp / PageDown 依實際行高翻頁並保留重疊的一行，避免大標題導致漏讀。反向跨快取分頁時，中文長段落保留目前的換行位置；未選取時複製的範圍依實際可見的行計算。

Markdown 目錄支援 `#` 至 `######` 標題，並排除程式碼圍欄內容。為保持大檔案的回應速度，每份 Markdown 目錄最多掃描前 **16 MiB**（純文字章節為前 256 MiB，日誌的時間索引掃描整個檔案，見「純文字與日誌」）、顯示 **16384 個標題**（足以容納上萬個標題的轉換規格書）；達到上限時目錄底部會提示。Setext（底線式）標題不收錄；內文閱讀與全文搜尋不受目錄範圍限制。重新載入（F5）會重新擷取目錄。

### 設定檔

預設寫入 %APPDATA%\FeatherMD\settings.ini，每次修改自動儲存。文件本身始終唯讀。主題、透明度與編輯應用程式分別儲存為 `theme`、`opacity`、`editor`；顯示圖片為 `images`（`true` / `false`，預設 `false`）；`font_family` 為空表示內文字型跟隨介面語言；自動檢查開關為 `update_check`，上次成功檢查的時間與所見的最新版本為 `update_checked`、`update_latest`。介面語言為 `language`（`system`、`zh-CN`、`zh-TW`、`en`、`ja`，預設 `system`）。無效值回到預設，帶 BOM 的 UTF-8 檔案也能讀取。

需要可攜式設定時，在 EXE 旁建立一個空的 **FeatherMD.ini**，之後設定隨這個檔案儲存。只想以單一檔案執行則不需要它。最近使用的檔案和文件內文不會寫入設定。

## 閱讀支援與明確邊界

- 文件支援 UTF-8 / UTF-8 BOM，以及依系統舊編碼讀取的非 UTF-8 文字（Big5 / GB18030 / Shift-JIS 等），內文為系統字型可顯示的 Unicode（不限語言）；介面文字支援简体中文、繁體中文、English、日本語。
- 標題、粗體、斜體、刪除線、行內程式碼、程式碼圍欄（常見語言醒目提示）、引文、清單、工作清單、分隔線、網頁連結、GitHub 風格表格（依視窗寬度自動排版）與常見 HTML 標籤。
- 圖片預設顯示替代文字；「顯示圖片」只控制本機圖片自動載入。網路圖片須逐張點選並確認（規則見上文）。
- HTML 只用於排版，不執行指令碼、不自動載入外部資源；不支援的標籤與 CSS 會被忽略。僅 http/https 連結可經確認後開啟。
- **這是低記憶體的分段預覽，不是完整的 CommonMark/GFM 瀏覽器轉譯器。** 除表格外按實體行排版；跨行強調、Setext 標題、複雜巢狀（例如清單裡的表格）、全域參照連結等可能不依完整規範呈現。
- 非起始分頁不掃描整份檔案來恢復狀態，跨頁的程式碼圍欄 / 清單上下文可能不完整，狀態列會提示。分頁從表格中間開始、看不到表頭時，這部分顯示為沒有表頭的表格。需要精確原文時請切換原始碼模式。
- 超長單行拆為最多 4096 位元組的安全 Unicode 片段，防止一個段落阻塞 UI。
- UTF-16/UTF-32 BOM 文件會明確提示先轉換成 UTF-8；其他無效的 UTF-8 位元組顯示替代字元並提示。不會自行改寫檔案。
- 全文搜尋仍需依序讀取資料，速度取決於裝置；搜尋可取消。網路磁碟機、傳統硬碟、檔案鎖定或系統負載也會影響速度。
- 自繪內文尚不具備完整的螢幕閱讀器語意。HTML 按行處理：跨多行的單一標籤、表格標籤（`<table>` 顯示為以「·」分隔的文字行）和巢狀很深的結構可能不依瀏覽器呈現；表格儲存格裡的圖片顯示替代文字。

- 純文字章節與日誌時間、層級依常見寫法辨識，不是完整的日誌格式剖析器；無法辨識的時間格式不進入時間索引。舊編碼文字裡沒有換行與 ASCII 字元的超長段落，分頁從段中開始時可能錯開一個字。

**不承諾「任意大小瞬間完整渲染」。** 目標是有上限的讀取、快速的第一頁和能即時回應的互動。

## 實測摘要

首版 v0.1.0 基準：本機 Windows 11 x64，Release 建置、暖快取、1 GiB 實體 UTF-8 Markdown：

- 背景讀取 + Markdown 解析第一頁，中位數 **1.05 ms**（30 次；不含 GDI 排版）。
- 隱藏真實視窗測試，從啟動到第一頁排版約 **75 ms**（單次，不保證冷啟動）。
- 測試結束時私有記憶體約 **7.1 MiB**，工作集約 **26.4 MiB**（含系統 GUI DLL）。
- 100 GiB **疏鬆檔案**通過頭尾 / 隨機讀取驗證；這不等於掃描了 100 GiB 的實際 Markdown 內容。

完整方法、數字和限制見 [PERFORMANCE.md](docs/PERFORMANCE.md)（簡體中文）。

v0.1.1 已複測相同的 1 GiB 檔案，第一頁排版 59.60 ms（單次暖快取），詳見效能記錄；不把不同輪次的波動解釋為普遍的效能提升。

## 從原始碼建置

安裝 Rust stable 和 Visual Studio Build Tools 的「使用 C++ 的桌面開發」元件 / Windows SDK，然後在 x64 Developer PowerShell 中：

~~~powershell
cargo +stable-x86_64-pc-windows-msvc test
cargo +stable-x86_64-pc-windows-msvc clippy --all-targets -- -D warnings
cargo +stable-x86_64-pc-windows-msvc build --release
~~~

產物：target/release/feathermd.exe。MSVC 靜態 CRT 設定位於 .cargo/config.toml。專案原始碼路徑含中文也可建置；不建議使用缺少 windres 的 GNU 工具鏈。

~~~powershell
# 不打擾桌面的隱藏視窗測試：主題、真實輸入搜尋、百分比跳轉、GDI 資源、結束
./scripts/ui-smoke.ps1
./scripts/navigation-smoke.ps1
./scripts/navigation-smoke.ps1 -Shape wrapped -Output ./test-artifacts/navigation-wrapped
./scripts/scrollbar-smoke.ps1
./scripts/window-smoke.ps1
./scripts/settings-smoke.ps1
# 表格排版、水平捲動、一鍵複製與預覽 / 原始碼按字元選取（複製內容經測試介面讀取，不改動剪貼簿）
./scripts/table-smoke.ps1
# 本機圖片：預設關閉；開啟後的尺寸、EXIF 方向、透明、徽章、連結、拒絕連接點與原因說明（圖片在測試中產生）
./scripts/image-smoke.ps1
# 四種介面語言的所有畫面：文字不得被截斷，儲存後立即切換
./scripts/i18n-smoke.ps1
# 編輯與更新測試使用替身編輯器和本機回送的替身 GitHub 介面，不存取網路
cargo +stable-x86_64-pc-windows-msvc build --release --example editor_probe --example update_server
./scripts/editor-smoke.ps1
./scripts/update-smoke.ps1

# 產生 1 MiB / 64 MiB / 1 GiB 實體測試檔案（約佔 1.1 GiB）
./scripts/make-fixtures.ps1
cargo +stable-x86_64-pc-windows-msvc run --release --example bench -- test-artifacts/fixtures/1073741824.md 30
~~~

核心讀取、解析與設定邏輯可在 Linux 上測試，GUI 僅支援 Windows。測試會建立並刪除一個 100 GiB 疏鬆檔案，實際佔用很小，需要支援疏鬆檔案的檔案系統。
