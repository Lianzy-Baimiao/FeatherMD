## 2026-10-17 商店关联测试：不要把 UWP 事件当成桌面打开方式

- `IApplicationActivationManager::ActivateForFile` 请求 Windows.File 契约；接收命令行的 packagedClassicApp 不应仅凭此 API 报错就被判定为文件关联损坏。先核对官方契约和真实 Shell 路径，不盲目补 capability / open verb。
- 保持清单不变，用 `SHAssocEnumHandlers` 精确匹配 AUMID 或安装路径，并通过 `IAssocHandler::Invoke` 传入单文件 IDataObject。该调用不返回 PID，需匹配新建的安装路径进程，再断言包身份与实际文档内容。不要改默认应用、仅按友好名称选择或改成直启 EXE 后冒充关联通过。
- WACK 的总体 PASS 也可能有可选失败：保留原始 XML、退出码、必选/可选统计和源代码解释。最终上架包应来自已验证的同一 artifact 并核对哈希，不能把另一轮构建的结果当作逐字节测试证据。

## 2026-10-17 用户允许副屏测试，但不能打扰主屏游戏

- 副屏测试不是先在主屏弹出再移动：必须在显示前限定所有顶层窗口与模态框的位置，并阻止激活；记录实际物理工作区与边界/前台违规。发现显示器或初始化约束失败时直接退出，不能另弹错误框。
- 当前用户授权才可传 `-SecondaryMonitor`；安装、证书信任和系统关联测试仍放到隔离 runner。副屏权限不等于允许自动使用 `-AllowDesktopUi` 或注入全局键鼠。
- 游戏按键会污染合成消息测试里的 `GetKeyState`。仅在明确测试模式下隔离物理 Ctrl/Shift，正常软件和普通 CI 不改；不要据一次通过就断言所有历史间歇失败都已解决。
- 禁止激活意味着无法覆盖真实 Tab/Enter 焦点行为。明确记录 deferred 并留给隔离 CI，而不是删断言后宣称同等测试通过。
- PowerShell `[string]` 参数的 `$null` 会变为空字符串，窗口标题可选筛选需用 `IsNullOrEmpty`。副屏保护要求的快照环境必须在每个启动路径设置，失败不能通过放松保护来解决。

## 2026-10-17 用户反馈：弹窗测试影响打游戏

- `Start-Process -WindowStyle Hidden` 不等于不打扰桌面：原生对话框可能在首次空闲时重新显示，测试关窗前会闪现或抢焦点。
- 本机默认只运行编译、单元测试、静态检查和打包校验；真实窗口、关联、安装卸载测试放到隔离 Windows runner，不通过反复弹窗来完成回归。
- 所有 smoke 脚本增加统一运行环境检查。本机 `-AllowDesktopUi` 必须取得当次用户明确许可，不能由代理为了跑完测试自行传入。
- 用户要求停止时，先停止测试父进程及其测试程序，保留用户运行的 dist 软件；如实记录中断和未跑项目。

## 2026-10-12 用户反馈：滚动条不可用，原生边框不符合要求，界面观感差

- 键盘翻页通过不代表滚动条可用；需要验证拖动滑块、轨道点击、滚轮、横向滚动和长文件定位的实际窗口路径。
- 自绘正文必须与窗口标题栏、边框、控件和状态栏保持统一，不能仅以替换颜色作为界面完成标准。
- 交付界面修改前应检查真实绘制截图、浅深主题及窄窗口，并明确区分脚本消息测试与真实鼠标操作。
- 启用 CS_DBLCLKS 的自绘窗口必须将 WM_LBUTTONDBLCLK 纳入控件按下路径；否则先点击再拖动会失败，单次 WM_LBUTTONDOWN 测试检测不到。
- 调用 DefWindowProc 进入系统移动/缩放循环前释放应用状态借用；WM_CANCELMODE 需要明确释放鼠标捕获。

## 2026-10-12 用户修正：需要可隐藏目录，独立工具栏占空间

- 阅读器优先给内容让位，避免标题栏下再堆一整行低频操作；把主要操作合入标题栏，其余收进菜单。
- 文档阅读导航应提供可折叠目录；标题提取必须后台、有界、可取消，不能让打开文件等待全文扫描。

## 2026-10-12 用户修正：目录开关重复

- 用户指出重复控件时，要结合控件归属理解反馈，不能默认应用标题栏的入口应该保留。
- 目录开关属于文档导航：展开时放在目录标题旁，收起后在内容左边缘提供恢复入口；不要同时在应用标题栏放第二个按钮。
- 界面预览必须来自最终构建；发布前检查展开、隐藏和窄窗口状态的控件数量与位置。

## 2026-10-12 用户修正：源码和明暗切换不能藏在更多中

- 高频阅读模式和明暗主题放在顶部，以可见状态的切换控件表达；更多只承载低频设置。
- 跟随系统是独立主题偏好，不能仅在启动时复制一次明暗值；系统变化需要实时刷新，手动选择要保留。

## 2026-10-12 用户测试：默认应用清单找不到 FeatherMD

- 注册表条目测试通过不等于 Windows 外壳清单可用；文件关联必须验证真实设置页与打开方式的可发现性。
- 先检查实际注册路径和运行的 EXE，再区分按应用列表、按扩展名选择器、右键打开方式三条路径；不能把启动设置当成功。

## 2026-10-12 顶部主题开关的阅读位置回归

- 只改变颜色时不要调用通用的重新排版路径：物理行内可能有很多换行位置，单独保存字节偏移会把阅读位置拉回段首。
- 检查用户眼前的交互状态，而不只是配置已保存；用 4096 字节以下的单段落验证切换前后的换行序号。
- 原生消息测试在缩放显示器上要和目标窗口使用一致的物理坐标，避免把测试进程的 DPI 虚拟化误判为产品拖动失败。

## 2026-10-12 用户反馈：关于窗口的系统弹窗外观太旧

- 关于窗口也要沿用阅读器的字体、留白和主题，不应为了原生而直接暴露默认 Task Dialog 外观；保持真正原生的键盘控件，并做一致的视觉设计。
- BS_OWNERDRAW 卡片需要验证 Tab 后 Enter 的实际行为，不能只测 BM_CLICK；默认对话框管理器可能把 Enter 交给默认“返回阅读”按钮。
- 隐藏窗口 PrintWindow 返回成功也可能全黑；复用进程内截图并断言背景像素，浅色和深色都要目视检查。

- 2026-10-12：用户说“首页上面 / 上面的 UI”时，先对齐主窗口顶部，而不是沿用上一项关于对话框的范围。顶部用紧凑图标和单入口主题选择，不再堆三段主题文字按钮；保留可发现的提示与快捷键。

## 2026-10-12 用户反馈：图标锯齿、需要自定义字体

- 自绘不等于精致；小图标不能直接用未抗锯齿的整数折线近似曲线。使用原生 GDI+ 矢量、圆端描边，检查原尺寸和最近邻放大截图，不用缩略图掩盖锯齿。
- 阅读字体与 UI 字体分离；测量和绘制必须用同一字体缓存，代码保留等宽。字体设置应有实时预览、取消草稿和持久化，不只是操作系统字体选择框。
- 原生跨进程测试用 WM_SETTEXT/WM_GETTEXT 操作 EDIT 内容，不能依赖 SetWindowText/GetWindowText 的远程标题行为；复合控件截图需要验证实际文字，而不只判断截图成功。

## 2026-10-14 图片、HTML、排版重写与更多皮肤

- “只显示本地图片”不能只看路径字符串：联接点、符号链接、映射的网络驱动器都能让本地路径通向网络。打开文件前逐级用 FindFirstFileW 看属性与重解析标记（不跟随链接），并拒绝仅在云端的 OneDrive 文件，否则读取本身就会触发下载。
- 解码器按内容而不是扩展名选格式：名为 .png 的图元文件同样会被解析。交给 GDI+ 之前先核对文件头签名。
- 先切掉 `?`/`#` 再判断设备路径会把 `//?/C:/a.png` 变成 `//`，被误判为网络地址；顺序敏感的规则要用测试覆盖每个分支。Rust 里 `a & !MASK == TAG` 是 `a & (!MASK == TAG)`，位运算比较一律加括号。
- 新子系统（GDI+ 解码线程）要定义关停顺序：进程级 GDI+ 只在解码线程结束后关闭，窗口退出时只等待有限时间。
- PowerShell 用 `[Drawing.Bitmap]::new($file)` 打开的图片会锁住文件，下一次快照写不进去；先复制到内存再释放。进程级 GDI 总数受对话框、字体缓存影响，验证某项资源是否释放时直接查询它自己的计数。
- `__COMPAT_LAYER=DpiUnaware` 压不住程序自己声明的每显示器 DPI 感知；96 DPI 的文字宽度用同一字体直接测量，CI 上再跑一次。
- 选区锚在“源字节 + 显示单元”上，而不是布局行号，缩放、改窗口大小和图片载入后选区才不会漂移；换行处去掉的空格在复制时补回。
- 新皮肤追加在 Theme::ALL 末尾，画廊另用一个显示顺序，已保存的皮肤序号和诊断查询都不受影响。

## 2026-10-13 表格与源码按字符选择

- 表格列宽按比例收窄会让本来只差几个像素的短列（“重新载入”）折行；先收窄最宽的列、给每列一个可读下限，比“数学上均匀”更接近读者期望。这是看实图才发现的，单元测试都通过。
- 横向滚动的作用范围要按内容决定：只移动放不下的那张表，正文和放得下的表不动。
- 冒烟测试的辅助函数不要叫 Move / Measure 等名字，PowerShell 会解析成 Move-Item / Measure-Object 的别名。
- GDI 计数在首次使用某功能后上升，要重复多轮确认是否继续增长，再判断是否泄漏；断言放在预热之后。
- 测试复制内容不要动用户的剪贴板：用仅在测试快照路径存在时启用的查询把待复制文本写到测试目录。

## 2026-10-13 一键复制与多语言界面

- 截断检查要量到每一处绘制的文字，并输出具体是哪段文字，而不是只给数量；英文“Open document”在固定宽度按钮里被截成“Open docume”，只有逐段测量才发现。按钮宽度按实测文字计算，而不是为一种语言写死。
- PowerShell 5.1：逗号运算符比 + 优先，`@('a' + "`t" + 'b', 'c')` 会把后面的元素都拼进一个字符串；需要制表符时写成 `"a`tb"`。函数调用后面同一行的语句会被当成参数吞掉（`StopReader [IO.File]::WriteAllText(...)` 从未写入 INI）。
- 测试辅助函数少了一个参数时 PowerShell 不报错，多出的实参被静默丢弃（`Query 61 $row` 永远查第 0 行）；新脚本的辅助函数签名要和旧脚本逐个对照。
- 同一线程里 SendMessage 先于 PostMessage 投递；投递命令后立刻查询会读到旧状态。只有会进入模态循环的命令才投递，其余用发送。
- 模态对话框在消息循环第一次空闲时才显示，过早隐藏会被它重新显示；隐藏后要确认连续几次仍是隐藏。
- 截图前等后台任务完成（目录提取），否则文档截图里会出现“正在提取标题…”。
- CI 运行器是英文系统：凡是跟随系统语言的界面，冒烟测试都要显式固定语言。

## 2026-10-13 默认窗口跟随显示缩放

- Per-Monitor V2 进程里 CreateWindowEx 的尺寸是物理像素；默认尺寸要在创建后按窗口 DPI 换算，并限制在显示器工作区内，在首次显示前完成。
- 本机显示缩放会在会话之间变化。比较页数、GDI 对象数或首屏时间前，先看冒烟结果里的 dpi；只在一种缩放下通过的脚本，可能藏着固定像素假设。
- 测试在新环境失败时，先用已发布的旧版 EXE 复现，区分本版回归与早已存在的问题，再决定改测试还是改产品。

## 2026-10-13 检查更新

- 用户需求与项目约束冲突（AGENTS.md“无网络获取”）时，按用户明确要求实现为最小、默认关闭、可审计的例外，并同步更新约束文档与界面措辞，在交付说明里写明。
- 不要相信网络库的超时选项：WinHTTP 的响应超时在回环实测中不可靠。需要“一定结束”的地方由自己的轮询截止时间保证，并用会卡住的本机服务器测试。
- 匹配菜单/界面文字的测试断言要先确认能失败：过滤条件写错（“发现新版本”不含“更新”）会让检查静默跳过。
- 截图用 WM_PRINT 时，隐藏子控件也会被画出来；按控件自身 WS_VISIBLE 过滤，否则截图与实际界面不符。
- 文档截图避免测试夹具里的虚构版本（v99 / 2030 年），使用与当前构建一致的真实状态。

## 2026-10-13 右键编辑、皮肤透明度与更矮标题栏

- 缩小图标时，非整数描边会横跨两行像素而发虚；描边取半像素、中心对齐像素网格，矩形图标坐标取整，曲线保留抗锯齿。用 96/120/144 DPI 截图放大检查，而不只看一种缩放。
- 皮肤配色先用对比度脚本计算，再出图；已有配色不达标（护眼次要文字 4.24:1）也要指出并修正。
- Windows PowerShell 5.1：Set-Content -Encoding utf8 会写 BOM，读取 INI 必须容忍 BOM；含中文的 .ps1 需要 UTF-8 BOM 才能被 5.1 正确解析。PowerShell 的 -match 不区分大小写，解析测试结果用 -cmatch。
- 验证视觉结论前先验证实验本身：固定窗口位置、确认参数确实生效、与旧版逐字节对比。DWM 边框色在本机无可见差别，就恢复原样，不把无效改动写成改进。
- 弹出菜单和模态对话框前释放 App 借用；跨进程可以用 MN_GETHMENU 读取真实菜单文字，并向菜单窗口投递方向键/回车完成选择。

## 2026-10-12 用户反馈：目录高亮不跟随点击

- 目录当前项不能只由顶行位置推导：文末或整页可见时跳转会被 clamp，所点标题无法成为顶行。用户点击是明确意图，应保留到阅读位置再次变化为止。
- 导航回归要覆盖短章节、多标题同屏和文末场景，并直接断言高亮索引，而不只断言字节偏移。
